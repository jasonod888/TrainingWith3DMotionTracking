# Kong Piano Playback Fidelity, Sustain Pedal & Acoustic Envelope Plan

## Goal and Context

When playing back a piano lesson in `Piano` audio mode (especially for lessons transcribed by **Kong** `music-piano-kong-v1`), the synthesized Grand Piano notes must match the natural sustain, phrasing, and attack clarity of the original piano recording as closely as possible.

This plan addresses both **model-data integration** (consuming Kong's sustain pedal predictions and defaulting `Piano` mode in real browsers to the live Grand Piano engine rather than the mono reference WAV) and the **4 browser playback implementation issues** that caused unnatural note durations and small playback anomalies.

## 1. Root Causes Addressed by This Plan

| # | Symptom | Root Cause in Current Code | Fix in This Plan |
| :- | :--- | :--- | :--- |
| **1** | Short notes cut off too early when the pianist is holding the sustain pedal | `PianoWorkspaceHarness.tsx` ignores `draft.pedal` and `manifest.pedal` (`MusicPedalSpan[]`), playing only the raw finger/frame `note.duration`. | Parse and retain `pedal` spans from Kong drafts/manifests; extend each note's **audible** ring until pedal lift (or max string ring / same-pitch re-strike) while keeping visual roll/waterfall durations unchanged. |
| **2** | Long notes drone like an electronic organ at 18% volume and then gate off abruptly in `40 ms` | `auditionEnvelope` in `piano-audition.ts` clamps decay at `HELD_FRACTION = 0.18` until `duration - 0.04s`, then drops to zero in `40 ms`. | Introduce `grandPianoEnvelope` for live/audition Grand Piano voices: continuous exponential string decay ($\tau$ scaled by pitch frequency $f_0$) with no artificial 18% plateau, plus a smooth `140–280 ms` damper release tail. |
| **3** | Random notes during playback sound "swallowed" or pop in without a hammer strike | `scheduleAt()` in `PianoWorkspaceHarness.tsx` uses a tight `60 ms` lookahead and treats any note with `start < now` (even by `2 ms` after a normal frame step) as a *mid-note seek* (`elapsed > 0`), which skips the attack peak and hammer transient. | Separate **initial play/seek pass** from **continuous frame ticks**. During continuous playback, any un-triggered note crossed since the previous frame tick is scheduled with `elapsed = 0` (full hammer attack). |
| **4** | Repeated notes on the same key sound hollow, metallic, or fluctuate in volume | `NotationAudio` stacks multiple oscillators on the exact same pitch/frequency without damping the previous string vibration, causing acoustic phase cancellation (comb filtering). | Track active voice per MIDI pitch in `NotationAudio`; when the same pitch is struck again at `startTime`, apply a `15 ms` anti-click damper micro-fade to the previous voice on that pitch. |
| **5** | Opening a new Kong draft plays the flat mono Python `preview.wav` instead of the Web Audio Grand Piano | `livePiano` was gated on `!verifiedPreview`, and Kong drafts include a `preview.wav` generated by `AdditiveReferenceRenderer` (`scripts/piano_render.py`). | When browser Web Audio (`AudioContext`) is available, default `Piano` mode to the **Live Grand Piano Synthesizer** (driven by Kong's notes + pedal + velocity), while keeping the `<audio>` preview element active when `AudioContext` is absent (JSDOM integration tests) or when `Rendered WAV` is chosen in Sound options. |

## 2. Detailed Technical Design

### Phase A: Sustain Pedal Resolution (`apps/web/src/music/piano-playback.ts` & `PianoWorkspaceHarness.tsx`)

1. **Retain Pedal Spans in Workspace State (`PianoWorkspaceHarness.tsx`):**
   - Add `const [pedalSpans, setPedalSpans] = useState<MusicPedalSpan[]>([]);` (importing `MusicPedalSpan` from `packages/lesson-schema/index`).
   - When loading a draft (`parseMusicDraftView`), set `setPedalSpans(draft.pedal ?? [])`.
   - When restoring a saved reference (`applyRestoredReference`), set `setPedalSpans(manifest?.pedal ?? [])`.
2. **Pure Audible-Duration Resolver (`apps/web/src/music/piano-playback.ts`):**
   - Export `resolveAudibleNoteTiming`:
     ```ts
     export type AudibleNoteTiming = {
       onset: number;
       soundingDuration: number;
       dampedByKey: boolean;
     };
     ```
   - Given a note (`{id, pitch, onset, duration}`), `pedalSpans: {onset: number; offset: number; type: 'sustain'}[]`, and the sorted list of next onset times for the same `pitch`:
     1. Compute raw key release: `const rawDuration = Math.max(0.05, note.duration ?? 0.35); const keyRelease = note.onset + rawDuration;`
     2. Check if any sustain pedal span covers `keyRelease` (or overlaps `[note.onset, keyRelease]` with `span.onset <= keyRelease && keyRelease < span.offset`).
     3. If pedal is down at `keyRelease`:
        - `const maxRing = Math.max(1.2, Math.min(6.5, 4.5 + (60 - note.pitch) * 0.04));`
        - `soundingEnd = Math.min(span.offset, note.onset + maxRing);`
        - `dampedByKey = false;`
     4. If pedal is up at `keyRelease`:
        - Give ultra-short notes a natural minimum acoustic ring (`0.22s`) so staccato notes or transcriber short frames don't click:
        - `soundingEnd = Math.max(note.onset + 0.22, keyRelease);`
        - `dampedByKey = true;`
     5. If another note of the **same `pitch`** has an onset `nextOnset` where `note.onset + 0.04 < nextOnset && nextOnset < soundingEnd`:
        - Cap `soundingEnd = nextOnset;` (the string is re-struck at `nextOnset`).
     6. Return `{onset: note.onset, soundingDuration: Math.max(0.08, soundingEnd - note.onset), dampedByKey}`.
   - **Visuals untouched:** Waterfall blocks, piano roll bars, and sheet music continue to read `occurrenceIntervals(document, offsetSeconds)` using the raw `note.duration`. Only the audio scheduler uses `resolveAudibleNoteTiming`.

### Phase B: Continuous Acoustic String Decay & Damper Tail (`apps/web/src/music/piano-audition.ts`)

1. **Preserve `auditionEnvelope` for Existing Unit Tests:**
   - Keep `auditionEnvelope(duration, pitch, velocity)` with its current points so `apps/web/tests/piano-audition.test.tsx` assertions on `auditionEnvelope` remain 100% satisfied.
2. **Add `grandPianoEnvelope(duration, pitch, velocity, dampedByKey = true): EnvelopePoint[]`:**
   - Models a real struck grand-piano string without the artificial `HELD_FRACTION = 0.18` organ plateau:
     - `level = velocityGain(velocity)`
     - **Release window (`release`):** `dampedByKey ? Math.min(0.16, duration * 0.35) : Math.min(0.28, duration * 0.4)` (smooth felt-damper release instead of a `40 ms` gate).
     - **Attack (`attack`):** `Math.min(velocityValue(velocity) >= 0.75 ? 0.0035 : 0.007, heldUntil * 0.2)`.
     - **Early bloom decay (`bloomEnd`):** `Math.min(velocityDecay(velocity) * 0.45, heldUntil * 0.45)`, decaying to `level * 0.52` as the initial hammer spike settles into the string.
     - **Continuous exponential string decay:**
       - Compute fundamental $f_0 = 440 \times 2^{(pitch - 69)/12}$ and register decay time constant:
         $$\tau = \text{clamp}\left(3.8 \times \left(\frac{220}{f_0}\right)^{0.35},\ 0.55,\ 5.5\right)$$
       - At `heldUntil = duration - release`, the string has naturally decayed to:
         `heldGain = Math.max(SILENCE * 2, level * 0.52 * Math.exp(-(heldUntil - bloomEnd) / tau))`
       - Add intermediate exponential curve checkpoints (e.g. at `bloomEnd + tau * 0.5` and `heldUntil`) and ramp to `SILENCE` (`0.0001`) at `duration`.
3. **Wire into `schedulePianoVoice`:**
   - Add optional fields `acousticDecay?: boolean; dampedByKey?: boolean` to `schedulePianoVoice`'s `note` parameter, and add `releaseAt?: (time: number, fadeSeconds?: number) => void` to the returned `PianoVoice`.
   - When `note.acousticDecay` is true (used by `NotationAudio`), compute `points = grandPianoEnvelope(note.duration, note.pitch, note.velocity, note.dampedByKey ?? true)`.
   - When `note.acousticDecay` is omitted/false (used by `piano-audition.test.tsx` direct unit tests), compute `points = auditionEnvelope(note.duration, note.pitch, note.velocity)`.

### Phase C: Same-Pitch String Re-strike & Damper Replacement (`apps/web/src/music/notation/notation-audio.ts`)

1. **Active Voice Tracking per Pitch:**
   - In `NotationAudio`, add `private activeByPitch = new Map<number, PianoVoice>();`.
   - In `schedulePianoVoice` (`piano-audition.ts`), implement `releaseAt(time: number, fadeSeconds = 0.015)`:
     - Safely cancels scheduled gain values at `time` (if `cancelScheduledValues` exists on `gain.gain`), ramps `gain.gain` to `SILENCE` at `time + fadeSeconds`, and stops the oscillator(s) at `time + fadeSeconds + 0.005`.
   - In `NotationAudio.playScheduledNote` and `NotationAudio.play`:
     - Before scheduling a new voice on `pitch` at `startTime`, check `const existing = this.activeByPitch.get(pitch)`.
     - If `existing` exists, call `existing.releaseAt?.(startTime, 0.015)` so the old vibration on that string damps cleanly as the new hammer strikes.
     - Store the new voice in `this.activeByPitch.set(pitch, voice)` and clear `this.activeByPitch` inside `stop()`.

### Phase D: Frame-Resilient Lookahead Scheduler (`apps/web/src/music/workspace/PianoWorkspaceHarness.tsx`)

1. **Eliminate Swallowed Attacks on Frame Steps:**
   - Precompute the pedal-resolved timings via `useMemo`:
     `const audibleTimings = useMemo(() => document ? resolvePerformanceAudibleTimings(document.performance, pedalSpans) : new Map(), [document, pedalSpans]);`
   - Inside the live scheduler `useEffect`:
     - Track `let initialPass = true;` and `let lastTime = sourceTime();` (resetting `initialPass = true` inside `stopVoices()` / `reset()`).
     - On `scheduleAt()`:
       - `const now = sourceTime();`
       - When `initialPass` is `true` (first tick after Play or Seek):
         - For notes where `start < now - 0.04 && now < end`: schedule mid-note (`elapsed = (now - start) / rate`, `windowSeconds = (end - now) / rate`).
         - For notes where `start >= now - 0.04 && start <= now + 0.12`: schedule fresh strike (`elapsed = 0`, `delaySeconds = Math.max(0, (start - now) / rate)`).
         - Set `initialPass = false; lastTime = now;`
       - When `initialPass` is `false` (continuous playback ticks):
         - `const windowFrom = Math.min(lastTime, now) - 0.04;`
         - `const windowTo = now + 0.12;` (120 ms lookahead buffer so Web Audio schedules sample-accurately ahead of the next animation frame).
         - Any un-triggered note with `start >= windowFrom && start <= windowTo` is scheduled as a **fresh strike (`elapsed = 0`, `delaySeconds = Math.max(0, (start - now) / rate)`)**!
         - Update `lastTime = now;`

### Phase E: Default `Piano` Mode to Live Grand Piano in Real Browsers (`PianoWorkspaceHarness.tsx`)

1. **Why:**
   - Kong lessons include a `preview.wav` asset rendered by Python's mono `AdditiveReferenceRenderer`. In a real browser (where `window.AudioContext` exists), the user wants the `Piano` switch to play the **Live Grand Piano Web Audio Synthesizer** (with unison strings, hammer transient, soundboard filter, velocity expression, and Kong's sustain pedal).
   - At the same time, `apps/web/tests/workspace-piano-integration.test.tsx` runs in JSDOM (where `window.AudioContext` is `undefined`) and tests `<audio>` synchronization when `preview.wav` is present.
2. **Clean Resolution:**
   - Add `const hasWebAudio = typeof window !== 'undefined' && Boolean(window.AudioContext || (window as {webkitAudioContext?: unknown}).webkitAudioContext);`
   - Add `const [preferRenderedWav, setPreferRenderedWav] = useState(false);`
   - Define:
     - `const verifyingPreview = Boolean(previewAsset && !preview.url && !preview.error);`
     - `const verifiedPreview = Boolean(previewAsset && preview.url && !previewStale);`
     - `const useWavPreview = verifiedPreview && (!hasWebAudio || preferRenderedWav);`
     - `const livePiano = audioMode === 'piano' && !useWavPreview && !verifyingPreview;`
   - In the Sound drawer (`data-ws-section="sound"`), when `verifiedPreview && hasWebAudio` is true, render an optional secondary toggle (`Live grand piano` vs `Rendered preview WAV`) defaulting to `Live grand piano`.
   - This guarantees:
     - In your real browser on both Kong and Basic Pitch lessons, clicking **`Piano`** always plays the rich **Live Grand Piano Web Audio Synthesizer**!
     - In `workspace-piano-integration.test.tsx` (JSDOM without `AudioContext`), `useWavPreview` is `true` when `preview.wav` is verified, so `acceptance 1` and `acceptance 2-4` pass without modification!
